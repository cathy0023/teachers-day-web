# 教师节礼物 — 三位老师的感谢网页

## 背景

- **来源**:家长(用户),2026-09-02 提出。教师节 2026-09-10 前需要完成。
- **场景**:用户的孩子在幼儿园,有三位老师 — 主班老师、配班老师、生活老师。希望在教师节当天各送一份"特殊的礼物"。
- **现状**:`/Users/chenyan/Documents/cy-play` 当前为空目录,无既有代码。
- **痛点**:市面上的礼物(花、卡片)同质化严重;希望做一份有温度、可长期保留、可线上分享,且能体现孩子本人声音的个性化礼物。
- **场景定位**:来广营朝花幼儿园,中五班 — 页面中需要体现这个具象环境(教室门、班级标识等)。
- **视觉素材方向(用户补充)**:
  - 向日葵 / 太阳花 — 作为页面主视觉/装饰元素,呼应教师节"向阳而生"的意象
  - 教室门 — 中五班的"教室门"作为入口隐喻,点击进入个人感谢页
  - 小朋友的小凳子 — 班级里的标志性物件,可作为按钮/卡片底座等装饰
  - 撒花动画 — 转场时或页面进入时的庆祝效果
- **素材现状**:
  - 三位老师的生活照:用户后续会上传(尚未提供)
  - 孩子的录音:暂未准备,先在网页里留占位

## 目标(用户视角)

- 为三位老师各自生成一个独立的感谢页面,体现"专属感"。
- 把老师的照片转成卡通形象,放在页面中,让礼物更有童趣。
- 页面中嵌入孩子的录音(留占位,后续手动替换),让老师能听到孩子的声音。
- 增加一个家长视角的"整体感谢页",作为三份个人礼物的总收尾。
- 最终部署到线上,生成一个可分享的链接。

## 范围

### 在范围内(In Scope)
- 一个 Vite + React 单页应用(SPA)
- 4 个核心页面:3 个个人感谢页 + 1 个整体收尾页
- 页面之间通过 React Router 切换,带过渡动画(Framer Motion)
- 每个个人页面包含:卡通形象(用户上传图片)、老师名字与职位、一段简短问候语、孩子录音占位、装饰性互动动画
- 整体收尾页:从家长视角感谢三位老师,可分别链接到三个个人页
- 录音以 `<audio>` 占位组件呈现,后续替换真实文件即可生效
- 静态构建产物部署到腾讯云 EdgeOne Pages / COS
- 文案以模板方式提供初稿,用户后续自行调整

### 不在范围内(Non-Goals)
- 用户账号系统、登录、密码
- 留言区、评论、点赞、互动数据收集
- 任何后端 API、数据库、用户追踪
- 第三方分析、统计、广告 SDK
- 自动背景音乐播放
- 暗色模式 / i18n 多语言

## 约束

- **技术栈**:Vite + React + React Router + Framer Motion,固定不换。
- **部署平台**:腾讯云 EdgeOne Pages 或 COS(用户选定,具体平台/账号在 PLAN 阶段确定)。
- **时间窗口**:8 天内(目标 2026-09-10 之前可访问)。
- **录音**:暂未准备,以 `<audio>` 占位呈现,接口稳定以便后续替换。
- **卡通形象**:由用户自己生成并上传(可能由豆包 / 即梦 / SeaArt 等工具产出),页面只负责展示图片。
- **文案**:我先写模板,用户后续自行调整;不在页面中虚构具体姓名/事件。
- **包体积**:不引入与功能无关的大型库;Lottie/3D 等被明确否决的方案不混用。
- **隐私**:页面访问不记录任何用户数据;不接入 GA / 百度统计等。

## 已讨论的方案

### 方案 A:Vite + React + Framer Motion SPA(已选 ✓)
- **核心思路**:单页应用,首页是 3 张老师卡片 → 点击进入个人页 → 最后一页家长整体感谢。Framer Motion 负责转场和细节动画。
- **优点**:
  - 动画流畅、转场自然,适合"礼物仪式感"场景
  - 组件复用度高,3 个个人页共用一个 `TeacherPage` 组件,数据驱动
  - 上手快,React Router + 一套 framer-motion 动画即可
- **缺点**:
  - SPA 在微信内置浏览器里偶尔有兼容问题,需上线前自测
  - 首屏需加载 JS 包,弱网体验略差
- **工作量预估**:中(预估 1 个完整工作日完成可上线版本)

### 方案 B:Vite 多页应用(多 HTML + CSS 动画)
- **核心思路**:4 个独立 HTML,顶部导航互链,纯 CSS keyframes 动画。
- **优点**:微信兼容好、刷新状态不丢、首屏快
- **缺点**:跨页动画难实现;若后续想加新页面要改构建配置
- **驳回理由**:动画表现力与"礼物仪式感"场景匹配度低,被用户否决

### 方案 C:Vite + React + Lottie 手绘动画
- **核心思路**:使用 Lottie 播放设计师动画,质感最好
- **优点**:动画质感最高、可复用、加载快
- **缺点**:需要准备 Lottie JSON 资源,或选免费 lottie 库(风格难统一)
- **驳回理由**:准备动画资产的成本与教师节剩余时间窗口不匹配,被用户否决

## 成功标准

- **可上线**:在本地 `npm run dev` 可正常浏览全部 4 个页面;`npm run build` 产物可被腾讯云 EdgeOne Pages 静态托管直接服务。
- **可访问**:部署后生成的链接在普通浏览器(桌面 + 手机端)均可正常打开。
- **可替换**:录音 `<audio>` 组件,只需将音频文件放到 `public/audio/` 下并修改数据源即可生效,无需改代码。
- **可替换**:卡通形象作为图片资源放在 `public/images/` 或 `src/assets/`,文件名与 `teachers` 数据一一对应。
- **可调文案**:所有问候语、感谢语集中在一个 `src/data/teachers.ts`(或类似)数据文件中,改文案无需动组件。
- **可导航**:3 张老师卡片、3 个个人页、1 个整体页之间导航顺畅,无 404 或错位。
- **基础质量**:页面在 iPhone SE(375px)及以上宽度无横向滚动;主要交互(播放录音、跳转页面)在主流浏览器(Chrome / Safari / 微信内置浏览器)可正常工作。
